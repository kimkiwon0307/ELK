# ELK

## 1장 로그의 기본

### 로그(Log)란 무엇인가?
1. 로그는 시스템이나 애플리케이션에서 발생한 사건을 기록한 데이터이다.
2. Log : 기록된 데이터
3. Logging : 로그를 생성하고 기록하는 행위

### 로그가 필요한 이유
1. 장애 발생 시 원인을 추적하기 위해서이다.

### 로그의 주요 사용 목적
1. 장애 분석
2. 운영 확인
3. 보안 감사
4. 요청 추적
5. 성능 분석

### 로그와 모니터링은 어떻게 다를까?
1. Prometheus는 서버와 애플리케이션의 상태를 수치로 관찰한다.
2. ELK는 수집된 로그를 통해 구체적인 사건을 검색하고 분석하는 데 사용한다.

### 실무에서 활용
1. Grafana에서 장애 알림 발생
2. Prometheus 메트릭 확인
3. Kibana에서 로그 검색
4. 원인 조사 및 조치

### 로그가 기록하는 것들
1. 좋은 로그란 장애가 발생했을 때 문제를 분석하는 데 필요한 정보를 담고 있는 로그이다.

### 로그에 기록하면 좋은 핵심 정보 8가지
1. 발생시간
2. 로그 심각도
3. 발생 서비스
4. 요청 식별자
5. HTTP 요청 방식
6. 요청 경로
7. HTTP 응답 상태
8. 발생 사건 설명

### 로그에 남기면 안 되는 정보
1. 비밀번호,
2. Access Token, Refresh Token
3. 주민등록번호
4. 신용카드 정보
5. 세션 쿠키나 API Key

### 로그는 언제 남겨야 할까?
1. 애플리케이션 시작
2. 중요한 요청 수신
3. 주요 작업 완료
4. 예상 가능한 문제
5. 외부 시스템 오류
6. 비정상 종료

## 로그의 레벨 - TRACE, DEBUG, INFO, WARN, ERROR, FATAL

## 로그 레벨(Log Level)이란?
1. 로그 레벨은 시스템에서 발생한 사건의 중요도나 심각도를 구분하기 위한 등급이다.
2. Logback의 주요 레벨은 TRACE < DEBUG < INFO < WARN < ERROR

## TARCE - 가장 상세한 기록
1. 프로그램 내부에서 아주 세부적인 흐름을 추적할 때 사용한다.
2. 주로 복잡한 실행 흐름을 확인할 때 사용

## DEBUG - 개발자가 문제를 분석할 때
1. 개발 중 변수 값, 계산 결과, 조건문 분기 등을 확인할 때 사용

## INFO - 정상적인 주요 작업
1. 서비스가 정상적으로 실행되는 과정에서 중요한 사건을 기록
2. INFO는 서버 시작, 작업 완료, 주요 상태 변경 등 운영상 의미 있는 사건에 사용한다.

## WARN - 경고
1. 당장 시스템이 실패하지는 않았지만 주의가 필요한 상황을 기록

## ERROR - 오류
1. 요청 처리 실패나 중요한 기능 장애처럼 정상적으로 작업을 완료하지 못한 상황에서 사용

## FATAL - 치명적 오류
1. 애플리케이션이 더 이상 정상적으로 동작하기 어려운 심각한 상황

## 로그 레벨을 설정하면 무엇이 달라질까?
1. 어느 수준 이상의 로그를 출력할 것인지 결정하는 기준으로 사용된다.

## 로그의 8가지 구성요소
1. Timestamp : 언제 발생했는가?
2. Level : 얼마나 중요한 사건인가?
3. PID : 어떤 프로세스인가?
4. Separator - 로그 필드 구분
5. Application - 어떤 애플리케이션인가?
6. Thread - 어떤 실행 흐름에서 처리했는가?
7. Logger : 어디서 기록했는가
8. Message : 어떤 사건인가

## MDC란 무엇인가?
1. MDC : Mapped Diagnostic Context : 로그에 요청 식별자와 같은 추가 정보를 연결할 수 있도록 제공하는 기능

## UUID란
1. UUID는 서로 다른 대상을 식별하기 위해 사용하는 고유 식별자이다.
