
# ELK 프로젝트 — 2장 2교시

## Elasticsearch Index 및 Document 생성과 데이터 저장

### 1. Elasticsearch 핵심 개념

| 개념 | 설명 |
|---|---|
| Index | 관련 Document를 관리하는 논리적 단위 |
| Document | JSON 형태의 데이터 한 건 |
| Field | Document를 구성하는 개별 항목 |
| Mapping | Field의 데이터 타입 등을 정의하는 규칙 |

**Document 예시**

```json
{
  "level": "ERROR",
  "service": "spring-app",
  "message": "Database connection failed",
  "status": 500
}
```

- Index: app-logs-lab
- Document: 위 JSON 데이터 전체
- Field: level, service, message, status

---

### 2. Mapping 데이터 타입

| 타입 | 역할 |
|---|---|
| keyword | ERROR 등 정확한 값 검색 |
| text | 문장이나 단어 검색 |
| integer | 정수 데이터 처리 |
| date | 날짜 및 시간 처리 |

**중요**
- keyword = 정확한 값 검색
- text = 분석된 텍스트 검색

---

### 3. Elasticsearch 주요 API

| HTTP 메서드 및 API | 역할 |
|---|---|
| PUT /app-logs-lab | Index 생성 |
| PUT /app-logs-lab/_doc/1 | ID 1번 Document 저장 |
| GET /app-logs-lab/_doc/1 | ID 1번 Document 조회 |
| GET /app-logs-lab/_search | Document 검색 |
| GET /app-logs-lab/_count | Document 개수 확인 |

**주의**
- 기존 ID에 PUT으로 다시 저장하면 해당 Document가 갱신될 수 있다.
- `_doc/id`에서 id는 실제 Document ID로 바꿔야 한다.

---

### 4. 주요 실습 명령어

아래 명령어는 2장 1교시에서 만든 인증 환경을 기준으로 한다.

#### ① Index 생성

```bash
curl --cacert ./http_ca.crt -u elastic \
  -X PUT "https://localhost:9200/app-logs-lab" \
  -H "Content-Type: application/json" \
  -d '{
    "settings": {
      "number_of_shards": 1,
      "number_of_replicas": 0
    }
  }'
```

※ 이번 교시의 전체 실습에서는 Mapping도 함께 지정했다.

#### ② Document 저장

```bash
curl --cacert ./http_ca.crt -u elastic \
  -X PUT "https://localhost:9200/app-logs-lab/_doc/1?refresh=wait_for" \
  -H "Content-Type: application/json" \
  -d '{
    "level": "ERROR",
    "message": "Database connection failed",
    "status": 500
  }'
```

#### ③ 특정 Document 조회

```bash
curl --cacert ./http_ca.crt -u elastic \
  "https://localhost:9200/app-logs-lab/_doc/1?pretty"
```

- `found: true` = 문서 존재
- `_id` = Document ID
- `_source` = 저장된 Document 내용

#### ④ Document 개수 확인

```bash
curl --cacert ./http_ca.crt -u elastic \
  "https://localhost:9200/app-logs-lab/_count?pretty"
```

#### ⑤ 전체 Document 검색

```bash
curl --cacert ./http_ca.crt -u elastic \
  "https://localhost:9200/app-logs-lab/_search?pretty"
```

#### ⑥ ERROR 로그 검색

```bash
curl --cacert ./http_ca.crt -u elastic \
  -X POST "https://localhost:9200/app-logs-lab/_search?pretty" \
  -H "Content-Type: application/json" \
  -d '{
    "query": {
      "term": {
        "level": "ERROR"
      }
    }
  }'
```

※ 마지막 검색은 `level`이 keyword로 매핑된 경우를 기준으로 한다.

---

### 5. curl 주요 옵션

| 옵션 | 의미 |
|---|---|
| --cacert | CA 인증서 지정 |
| -u | 사용자 인증 |
| -X PUT | HTTP PUT 요청 |
| -X POST | HTTP POST 요청 |
| -H | HTTP 헤더 지정 |
| -d | 요청 본문 데이터 전송 |
| ?pretty | JSON 결과를 읽기 쉽게 출력 |
| refresh=wait_for | 데이터가 검색 가능해질 때까지 대기 |

---

### 6. Document 저장 후 검증 방법

**핵심: 저장 성공 응답과 실제 데이터 조회는 구분해야 한다.**

1. 저장 API에서 생성 성공 응답 확인
2. `_doc/{id}`로 특정 문서 존재 및 내용 확인
3. `_count`로 전체 문서 개수 확인
4. `_search`로 조건에 맞는 문서 검색 확인

**API 차이**

- `_doc/{id}` = 특정 문서 조회
- `_search` = 조건에 맞는 문서 검색
- `_count` = 문서 개수 확인

주의: `_count`가 3이라고 해서 3개 문서의 내용까지 모두 정확하다는 의미는 아니다.

### 7. 기본 장애 대응

| 문제 | 확인할 내용 |
|---|---|
| 400 Bad Request | JSON 형식 및 Mapping |
| 401 Unauthorized | 계정 및 비밀번호 |
| 404 Not Found | Index 이름 및 Document ID |
| 검색 결과 0건 | 검색 조건, Mapping, 색인 반영 |
| Connection refused | 컨테이너 상태 및 9200 포트 |
| Index 생성 실패 | 기존 Index 존재 여부 및 오류 응답 |

**장애 점검 원칙**

1. 실제로 데이터가 저장되었는가?
2. Index와 Document ID가 올바른가?
3. 검색 조건과 데이터 타입이 적절한가?
4. 검색에 데이터가 반영되었는가?

---

### 8. 확인문제 및 정답

**Q1. Index란?**

정답: 관련 Document를 관리하는 논리적인 단위

**Q2. Document란?**

정답: JSON 형태의 데이터 한 건

**Q3. Mapping의 역할은?**

정답: Field의 데이터 타입 등을 정의한다.

**Q4. 특정 Document ID를 조회하는 API는?**

정답: `/{index}/_doc/{id}`

**Q5. level을 keyword로 설정한 이유는?**

정답: ERROR, INFO 등 정확한 값을 검색하기 위해서이다.

**Q6. 저장한 Document가 정상인지 어떻게 검증하는가?**

정답:
1. `_doc/{id}`로 특정 문서 존재와 내용 확인
2. `_count`로 문서 개수 확인
3. `_search`로 원하는 데이터 검색 확인

---

### 9. 핵심 암기

- Index = 문서 관리 단위
- Document = JSON 데이터 한 건
- Field = 개별 항목
- Mapping = 데이터 타입 정의
- PUT = 리소스 생성 및 갱신에 사용
- GET = 데이터 조회
- `_doc/{id}` = 특정 문서 조회
- `_search` = 조건별 검색
- `_count` = 문서 개수 확인
- keyword = 정확한 값 검색
- text = 분석된 문자열 검색

**가장 중요한 한 문장**

Elasticsearch에서는 Index를 생성하고 Document를 저장한 뒤, `_doc`, `_count`, `_search` API를 이용해 데이터가 정상적으로 저장되고 검색되는지 검증한다.
